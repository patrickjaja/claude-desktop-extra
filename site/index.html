Quick Start

Install in seconds

Pick your distro. x86_64 and aarch64 are supported everywhere except Nix (x86_64 only); the repos pick the right architecture. New upstream releases reach you through your package manager.

# From the AUR (or: paru -S, Manjaro: pamac build)
yay -S claude-desktop-extra
Arch, Manjaro, Omarchy, CachyOS, EndeavourOS and other Arch-based distros. Updates arrive through yay -Syu; x86_64 and aarch64. The PKGBUILD downloads the prebuilt, SHA256-pinned release tarball and repackages it, no compiling. No AUR helper? Use the signed pacman repository →
# Add the repo + signing key, once
curl -fsSL https://patrickjaja.github.io/claude-desktop-extra/install.sh | sudo bash
# Install
sudo apt install claude-desktop-extra
Requires Ubuntu 22.04+ / Debian 12+ (glibc 2.34+); amd64 and arm64. Replaces Anthropic's own claude-desktop package if installed (same files). Cowork packages come in as Recommends. Updates arrive through apt upgrade.
# Add the repo + signing key, once
curl -fsSL https://patrickjaja.github.io/claude-desktop-extra/install-rpm.sh | sudo bash
# Install
sudo dnf install claude-desktop-extra
x86_64 and aarch64. Cowork packages come in as weak deps. Updates arrive through dnf upgrade.
# Try without installing
nix run github:patrickjaja/claude-desktop-extra

# Or install persistently
nix profile install github:patrickjaja/claude-desktop-extra
x86_64 only. Flake users: add inputs.claude-desktop.url = "github:patrickjaja/claude-desktop-extra";, update with nix flake update. Cowork tools are baked into the closure. NixOS details →
# Download Claude_Desktop-<version>-x86_64.AppImage from the latest release, then:
chmod +x Claude_Desktop-*-x86_64.AppImage && ./Claude_Desktop-*-x86_64.AppImage
Any distro, including immutable ones (Bazzite, Silverblue/Kinoite, SteamOS, Universal Blue). No root required; the claude:// sign-in handler registers itself on first launch. Delta updates with appimageupdatetool; works with AppImageLauncher and Gear Lever. Needs the host's PipeWire client library (libpipewire-0.3.so.0, present on every desktop with PipeWire); for the Claude Code shell sandbox, bubblewrap and socat. aarch64 build in the same release. Latest release →
Cowork (the agent VM) is optional and needs QEMU/KVM: setup below. Repository signing key (APT, DNF and pacman): 825A 7D15 D78B ABE4 5646 D5DF 3824 09F5 9790 8867, check it with curl -fsSL https://patrickjaja.github.io/claude-desktop-extra/gpg-key.asc | gpg --show-keys --with-fingerprint. The Extra section in Claude's Settings
Code tab

The Code tab as an IDE

Community switches that make the Code tab work like VS Code, plus help with long sessions and pull requests. Each is off by default; turn it on in Settings → Extra → Community. Off leaves the Code tab as Anthropic ships it.

Files quick open

Ctrl+P finds a file and opens it in the Files panel; path:42 jumps to a line, and words match in any order (user service finds user-service.spec.ts).

Panel tabs

Diff, terminal, browser and files open as tabs instead of a shrinking split; each gets the full width and keeps its state, Ctrl+1-9 switches.

Diff view modes

The diff panel shows Working tree, Branch changes or Latest turn, against the branch you actually forked from, with expand/collapse all.

Load large sessions in full

Long Code sessions open in full instead of hiding their older part behind "This session is too large to load in full". Uses more memory on huge sessions; takes effect after a restart.

"Allow always" for new sessions

When Claude wants to start another Code session, a system dialog asks with Deny, Allow once or Allow always, instead of the in-chat card. Details

Pull requests

Auto-fix notices when a PR is ready to merge and for comments after it merges (Claude reports and waits, it never merges), trusted Auto-fix PR authors, and a delay before auto-archive with a "Keep this session" button. Auto-fix notices - auto-archive delay

Ctrl+P quick open over the Files panel, and the side panels as tabs. docs/code-tab.md
Models

Other providers' models, next to Claude

Two ways to use non-Anthropic models, depending on whether you keep your claude.ai login.

1P - keep your login

Custom models

Use models from other providers (DeepSeek, Kimi, GLM, MiniMax, Qwen, OpenRouter, Opper, a gateway, or Anthropic's API on your API credit) in the Code tab's model picker, next to Anthropic's. Sessions on them use your own key; everything else stays on your subscription. Add a provider from a preset in Settings → Extra → Models, fetch its models and turn the switch on. Claude can also use them by itself: every custom model is a sub-agent type, and workflows can name it. Off by default. docs/custom-models.md →

3P - a gateway replaces the login

Allow non-Anthropic models

In third-party mode, upstream silently drops gateway model IDs that do not look Anthropic (DeepSeek, Qwen, GLM, Kimi, gpt-oss, ...) and falls back to the default model. This opt-in switch in Settings → Extra → Community keeps them in the model list, the picker and running sessions; HIPAA and admin model allowlists still apply. Restart after switching. The Opper cookbook covers both routes; more recipes in docs/cookbook/.
Computer Use

Desktop automation on every session type

Screenshot, click, type, scroll and teach mode, on for every account and every session type. The official build's own Linux Computer Use is a staged rollout that needs a RemoteDesktop portal (GNOME 46+, current Plasma) and skips wlroots; our bundled bridges take precedence and need nothing installed.

Session Compositors Input and screenshots
X11 / XWayland GNOME, KDE, i3, ... x11-bridge (bundled)
Wayland (wlroots) Sway, Hyprland, Niri wlroots-bridge (bundled)
Wayland (GNOME) GNOME Shell, PipeWire >= 1.0.5 gnome-portal-bridge (bundled)
Wayland (KDE) KDE Plasma 6.6+ kwin-portal-bridge (bundled)
Older GNOME and KDE sessions, NixOS GNOME / KDE and other compositors take a fallback: per-session matrix.

Community features

Switch on what you need

The optional features in Settings → Extra → Community, in the same groups the app uses. Each has its own switch; all but the Theme picker start off, and off keeps Anthropic's behavior.

Code
Code tab: panels, files, diffs and sessions
Panel tabs applies live
Shows the Code tab's side panels as tabs, so the panel you are using gets the full width. Off gives you the normal split layout back. Applies live.
Files quick open applies live needs restart
Press Ctrl+P on the Code tab to jump to a file by typing part of its name. Off leaves the Files panel as Anthropic ships it. The hotkey applies live; the improved search reaches the file index after a restart.
Diff view modes applies live
Adds a scope dropdown to the Code tab's diff panel: Working tree, Branch changes or Latest turn. Off leaves the panel as Anthropic ships it. Applies live.
Load large sessions in full needs restart
Opens very large sessions in full instead of hiding their older part. It uses more memory and time on huge sessions; off keeps Anthropic's limits. Takes effect after a restart.
Native dialog with 'Allow always' for starting other sessions applies live
Asks with a system dialog (Deny, Allow once, Allow always) when Claude wants to start another Code session. Off (the default) keeps Anthropic's in-chat card, and turning it off forgets every remembered approval. Applies live.
Pull requests
Auto-fix and auto-archive for your GitHub PRs
Trusted Auto-fix PR authors applies live
Lets Auto-fix also handle PRs opened by other GitHub users or bots. Empty by default, so only the signed-in gh user counts; add one host/login per line, for example github.com/my-app[bot]. Applies live to future attempts.
Auto-fix notices: ready to merge, comments after merge applies live
Tells the Code session when a PR with Auto-fix on is ready to merge, and passes on new comments after it merges. Claude only reports them and waits for you - it never merges. Costs one GitHub read per Auto-fix PR and one model turn per notice. Applies live.
Auto-archive delay after a PR merges or closes applies live
Waits a chosen time after a PR merges or closes before its Code session is archived. Only used while PR auto-archive is on; the Code session also shows the time left and a Keep this session button. Applies live.
App and window
Look and behavior of the app window, tray and theme
Hide window controls needs restart
Opens the main window without frame, buttons or shadow, which removes the thin border some window managers (XFCE, i3, Awesome) leave. You minimize, maximize and close through your window manager; the native titlebar wins if both are on. Takes effect after a restart.
Native titlebar needs restart
Uses your system's own window frame and titlebar instead of the app's. It adds a second bar above the app's header and wins over "Hide window controls". Takes effect after a restart.
Transparent window applies live needs restart
Makes the main window see-through so your desktop, or the blur your compositor adds, shows through. It has no window buttons or shadow and needs the integrated titlebar. The switch takes effect after a restart; the Transparency slider applies live.
Always use the white tray icon applies live
Keeps the tray icon white instead of following the theme. Off follows the theme like the stock app. Applies live.
Theme picker applies live
Press Ctrl+Shift+T to open a searchable gallery of themes and apply one with a click. Applies live.
Developer tools applies live needs restart
Lets Ctrl+Alt+I open the browser developer tools for the focused window. The shortcut applies live; the app menu entry appears after a restart, and an organization that turned developer mode off keeps it off.
Models and 3P
Extra models and gateway options
Custom models applies live
Adds models from Anthropic-compatible providers (DeepSeek, OpenRouter, your own gateway) to the Code tab's model picker. Sessions on them use your own key; set them up in Settings > Extra > Models. Applies live.
Allow non-Anthropic models needs restart
Keeps models such as DeepSeek, Qwen, GLM or Kimi in the model list when you use a third-party (3P) gateway. 3P mode only: set it while in 3P mode. Takes effect after a restart.

How it works

66 patches on the official build, and growing

We start from Anthropic's official Claude Desktop Linux .deb, apply small JavaScript patches to its app.asar, and repackage the result for each distro.

1. Ingest

Download the official .deb from Anthropic's apt repo, verify GPG and SHA256, extract it.

2. Patch

Apply the patches to the extracted bundle. A patch that stops matching fails the build, and a patch is removed once upstream ships the behavior.

3. Repackage

Build the pacman package, .deb, .rpm, AppImage and Nix flake from the patched tree, and publish them to the repos.

Where Anthropic lacks compatibility: general Linux patches for the tray, portals, Wayland and X11, the sandbox, Cowork on non-Debian distros and more, plus the shared infrastructure the features build on (the Extra settings pages, the theme engine, profiles). Fleet rollout

managed-settings.json

For MDM rollouts, headless servers and scripted provisioning. Try it end to end with a local LiteLLM proxy first: 5-minute quickstart → Vertex AI, Bedrock and Foundry: Linux guide →

// /etc/claude-desktop/managed-settings.json
{
  "inferenceProvider": "gateway",
  "inferenceGatewayBaseUrl": "http://127.0.0.1:4000",
  "inferenceGatewayApiKey": "sk-your-gateway-token",
  "inferenceGatewayAuthScheme": "bearer",
  "inferenceModels": [
    { "name": "claude-opus-4-8" },
    { "name": "claude-sonnet-4-6" }
  ],
  "disableDeploymentModeChooser": true,

  // Surfaces - Chat, Cowork, Code tabs
  "chatTabEnabled": true,
  "coworkTabEnabled": true,
  "isClaudeCodeForDesktopEnabled": true
}

One file, no Anthropic sign-in. Every key must be one the running build knows, or the whole file is ignored. See every key →

Troubleshooting

When something goes wrong

Logs are in ~/.config/Claude/logs/ (3P mode: ~/.config/Claude-3p/logs/, named profiles: ~/.config/Claude-<profile>/logs/). Common problems and known limitations: docs/troubleshooting.md. A white screen or GPU crash: CLAUDE_DISABLE_GPU=1 or CLAUDE_GPU_BACKEND=angle-gl.

# Reporting a bug: attach both files to your issue
claude-desktop --diagnose > diagnose.txt
cp ~/.config/Claude/logs/claude-patches.log .   # 3P mode: ~/.config/Claude-3p/logs/claude-patches.log
